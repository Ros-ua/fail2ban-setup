# fail2ban-setup

Защита ssh от подбора пароля одной командой. Debian 11/12, Ubuntu.

```bash
wget -qO f2b.sh https://raw.githubusercontent.com/Ros-ua/fail2ban-setup/main/fail2ban.sh && bash f2b.sh 2>&1 | tee fail2ban.log
```

В конце скрипт печатает **ГОТОВО** или **ВНИМАНИЕ** — и это не украшение, а смысл всей затеи.

## Зачем свой, если готовых полно

Проверено 26.08.2026 на трёх живых серверах. Популярный одно-кнопочный скрипт
`FunctionClub/Fail2ban` был поставлен на все три и:

- **на Debian 12 не запустился вовсе.** В нём жёстко вбито `logpath = /var/log/auth.log`.
  Этого файла на Debian 12 нет: в образах многих хостеров не ставится `rsyslog`, и записи
  о входах живут только в журнале systemd. Служба падала при старте с
  `ERROR Failed during configuration: Have not found any log file for sshd jail`;
- **при этом печатал «Fail2ban is now runing on this server now!»** — безусловным `echo`
  в конце, ни разу не спросив `systemctl is-active`. Сервер стоял без защиты, а хозяин
  был уверен, что защищён;
- **на Debian 11, где он «сработал», он не дал ничего.** Его тюрьма `ssh-iptables`
  забанила за всё время **0 адресов**. Банила штатная тюрьма `sshd` из
  `/etc/fail2ban/jail.d/defaults-debian.conf`, который кладёт **сам пакет fail2ban**
  (проверяется через `dpkg -S`). То есть весь эффект давал обычный `apt install fail2ban`.

Что скрипт добавил на самом деле — три опасные настройки:

| настройка | что делает |
|---|---|
| `maxretry = 1` | **один** промах, даже свой собственный, даёт бан |
| `bantime = -3600` | отрицательное значение = бан **навсегда** |
| `ignoreip = 127.0.0.1` | и всё. Свой рабочий адрес в белый список не попадает |

Вместе это ловушка: одна опечатка при входе — и ты снаружи навсегда, вернуться можно
только через консоль хостера.

## Что делает этот скрипт

1. **Сам заносит в белый список адрес, с которого ты подключён** (`$SSH_CLIENT`).
   Это главное: без этого любая защита от подбора однажды забанит хозяина.
   Дополнительные адреса — аргументами: `bash f2b.sh 1.2.3.4 5.6.7.0/24`
2. **Определяет, где лежат записи о входах, по факту наличия файла**, а не по версии
   системы: есть `/var/log/auth.log` → `backend = auto`, нет → `backend = systemd`
   (и доставляет `python3-systemd`, без которого журнал не прочитать).
3. Выбирает способ бана: `iptables-multiport`, а если iptables нет — `nftables-multiport`.
   С UFW уживается.
4. Настройки: `maxretry = 5`, `findtime = 1h`, `bantime = -1` (навсегда — но теперь это
   безопасно, потому что свой адрес защищён).
5. **Проверяет себя и говорит правду.** Служба active? Поднимется после перезагрузки?
   Тюрьма работает? Твой адрес защищён от бана — причём это спрашивается **у самого
   fail2ban** (`fail2ban-client get sshd ignoreip`), а не смотрится в файл: файл может
   быть верным, а служба его не перечитать. Хоть одна проверка провалилась — печатает
   **ВНИМАНИЕ** и выходит с ошибкой.

Проверка проверена подсадкой поломок: убран свой адрес из белого списка, испорчено
определение журнала, выключена тюрьма, остановлена служба — **все четыре пойманы**.
